# UX review: what to fix, enhance and add

Date: 2026-11-11, version 0.2.61 (117e50e).

Scope and method: the app as a user meets it, read from README.md, FEATURES.md, BACKLOG.md,
CHANGELOG.md, docs/known-limitations.md, docs/ux-decisions.md, docs/remote.md and targeted
reads of `crates/app/src/` and `crates/term-core/src/`. **The app was not run for this
review**: nothing here was seen on screen, so visual claims (contrast, spacing, truncation)
are left to the earlier review, which had screenshots.

Relation to [ux-review.md](ux-review.md) (2026-10-25, validated 2026-11-01): its findings are
not repeated. Its Tier 1 and Tier 2 are still open in BACKLOG.md and still the right next
batch. This review looks for what that one and the backlog do not cover, and says where a
tracked item deserves a higher priority. IDs here are F (fix), E (enhance), M (missing) to
avoid clashing with the old numbers.

## Verdict

The core promise works and is unusually well thought through: per-tab agent status read from
the agents' own hooks, attention jump, groups, hover cards, in-place agents in shell tabs,
safeguards that can't be switched off, and settings that survive hand edits.

The weak spots, in order of how much they cost a user:

1. **Losing work silently**: unsaved viewer edits at window close, tab organisation after a
   crash, a second window's tabs, the agent's last screen, permanently deleted files.
2. **The attention promise stops at the window edge**: nothing reaches a user who is in
   another application, and remote tabs have no status at all.
3. **Baseline terminal comforts are missing**: no right-click menu, no paste protection, no
   scrollback control, no jump between prompts.
4. **Nothing explains the app from inside it**: eight status badges, shell integration and
   the attention key are documented only in an 820-line README.
5. **The spec says "side by side" and "panes"**, but one terminal shows at a time and split
   panes are not even in the backlog.

## Fix

### F1. Window close drops unsaved file edits
- **Done** (2835a26): closing the window asks once for every file with unsaved edits (Save
  all / Discard / Cancel); a failed or cancelled save keeps the window open.
- Problem: closing a tab asks about unsaved viewer edits, closing the window does not
  (known-limitations: "Closing the window still drops unsaved file viewer edits without
  asking"). A user who edited `settings.json` or a plan file and hits the window's close
  button loses the edit with no sign.
- Suggestion: the window-close question (`busy_close.rs`, `request_close_window`) already
  lists busy tabs once; add the files with unsaved edits to the same dialog, with Save all /
  Discard / Cancel. FEATURES already calls the unsaved-edit confirmation a safeguard that
  always applies.

### F2. Tab organisation is saved only at window close
- **Done**: opening, closing, renaming, pinning, moving, grouping, coloring and collapsing save
  at once (`sync_order` and each gesture queue a snapshot on the background writer).
- Problem: names, pins, order, groups and colors reach `tabs.json` at window close or at a
  shell's next command (known-limitations). A crash, a killed session, a power cut or a
  Windows update restart loses a carefully arranged workspace. Arranging tabs is the main
  thing the sidebar asks the user to invest in.
- Suggestion: queue a snapshot on the existing background writer whenever the layout changes
  (rename, pin, move, group, color, open, close). The writer already coalesces in order, so
  the cost is one small file write per gesture.

### F3. A second window gives no hint that it is different
- **Done** (option A): a guest window shows an info notice until closed, unless Restore
  previous tabs is off.
- Problem: only the first instance restores and saves tabs; a later one opens a single tab and
  never writes them (`main.rs:166-173`, `TabOwnership::Guest`). Nothing in the UI says so. A
  user who builds groups in the second window, closes both and reopens finds them gone, and
  cannot tell why.
- Option A: a persistent, dismissible notice in a guest window: "Tabs in this window are not
  saved: another Agent Workspace window owns the saved tabs." Cheap and honest.
- Option B: starting the app again focuses the running window and opens the requested tab
  there (single instance, like most terminals' "new tab in existing window"). Fixes the cause,
  but removes two real windows, which some users want on two monitors.
- Recommendation: A now; B only together with split panes or true multi-window support.

### F4. The agent's last screen disappears when it quits (reopens a recorded decision)
- Problem: when Claude Code or Copilot CLI exits with code 0, the tab starts a shell and "the
  agent's output is not kept" (README, Design decisions). That screen holds exactly what the
  user wants next: the final summary, the cost line and the `claude --resume <id>` hint. It
  is the one moment the app throws away terminal content the user did not ask to clear.
- Suggestion: keep the launch design (agent runs directly, no shell around it) and only change
  what happens to the grid: start the fallback shell in the same terminal below the agent's
  last output, so it scrolls into scrollback like any earlier command. If the terminal cannot
  be reused across two processes, print the agent's last screen into the new session before
  the shell's first prompt.
- Needs the user: it changes a decision recorded in the README.

### F5. Delete in the explorer is permanent
- Problem: Delete "deletes for good, not to the trash", one row away from Rename in a
  right-click menu. The confirmation says so, but every file manager and editor the user knows
  uses the trash, so the dialog reads as routine.
- Suggestion: move to the system trash (Windows Recycle Bin, freedesktop trash); fall back to
  the permanent delete, with today's wording, where no trash exists (network mounts, WSL
  paths). A new dependency needs a `cargo deny` license check.

### F6. A multi-line paste runs at once in programs without bracketed paste
- Problem: without bracketed paste the app turns every newline into Enter and sends the text
  (`keys.rs:73`). In cmd, in a shell started inside a tab, or over a plain ssh, pasting a
  copied snippet with a trailing newline runs it immediately; several lines run one after
  another. Windows Terminal and iTerm2 ask first.
- Suggestion: when the terminal is not in bracketed-paste mode and the text contains a
  newline, ask once ("Paste 4 lines? They will run as commands") with the text previewed, in
  the style of the clipboard-write notice above the terminal. Bracketed paste (bash, zsh,
  PowerShell with PSReadLine, both agents) stays immediate. This is a safeguard, so by the
  spec's own rule it needs no switch.

### F7. Remote sessions end when the tab or the app closes
- Problem: docs/remote.md opens with "The sessions keep running when the laptop disconnects,
  and the app can attach to them again, like tmux", but "Closing the app ends its remote
  sessions, like local ones" and remote tabs are not restored. Only a lost connection keeps a
  session alive. Shutting the laptop lid may keep an agent running; quitting the app properly
  kills it. That is the opposite of what a user would guess.
- Suggestion: closing a remote tab (and the window with remote tabs) asks "End the session on
  <host>" or "Leave it running"; sessions left running are listed in the host's `+` submenu to
  attach again. The backlog's remote "Restore" item covers reattaching at start; the
  detach-or-end choice on close is not in it and should ship with it.

### F8. Remote tabs look like local ones but report nothing
- Problem: remote tabs have no agent status, branch, history or explorer (docs/remote.md). The
  row shows a server icon, but a remote Claude waiting for permission looks idle. The user
  learned to trust the badge on local tabs.
- Suggestion until M3 is built: the hover card's status line reads "Status isn't available for
  remote tabs yet", and the explorer shows the planned "Files on <host> aren't available yet"
  (already in the backlog). A bell from the remote program should still raise Needs attention;
  check that it does.

### F9. "Discard changes?" has no Save
- **Done** (2835a26): "Save changes?" with Save (default, Enter) / Discard / Cancel.
- Problem: opening another file or closing the viewer with unsaved edits offers Discard or
  Cancel only (`file_viewer.rs:257`). To keep the edit the user must cancel, press Ctrl+S and
  repeat the action.
- Suggestion: Save / Discard / Cancel, Save as the default button.

### F10. Documentation is written for the builder, not the user
- The README is 823 lines and mixes the user guide with payload casing of Copilot hooks,
  verification notes, manual test checklists and release mechanics. A new user cannot find
  "what do the badge colors mean" or "how do I get status for my alias" without reading it all.
  There is no screenshot.
- Suggestion: README = what it is, one screenshot, install, a two-minute quick start, the
  fifteen shortcuts that matter, links. Move the rest to `docs/user-guide.md` (by task), keep
  the Copilot verification notes and the manual checks under `docs/`.
- Contradictions and leftovers found while reading:
  - Product name: "Agent Workspace" in the UI, "Bowarp" in README:276 and in the Copilot
    extension's folder name, `agentws` in file and variable names. Pick one user-facing name.
  - README:493 says the viewer width "is not saved yet"; known-limitations says it is saved as
    `file_viewer_fraction`.
  - README:106 and :135 say a plain click opens a link; FEATURES.md:28 says Ctrl+click.
  - FEATURES.md:29 ends with a stray "www.google.ca".
  - README:226 says the folder follows `cd` on Linux only, while the explorer section says it
    follows in bash, zsh and PowerShell tabs on other platforms too.

## Enhance

### E1. A right-click menu in the terminal
- Today the right button is only forwarded to programs that track the mouse
  (`terminal_view.rs:1391`); otherwise it does nothing. Copy, paste and search exist only as
  shortcuts, which Windows users in particular will not guess (Ctrl+Shift+C).
- Suggestion: Copy (disabled without a selection), Paste, Select all, Search, Clear
  scrollback; on a link: Open, Copy link. With mouse reporting on, Shift+right-click opens it,
  matching the Shift rule for selection. Each entry shows its shortcut, which also teaches the
  keys.

### E2. Scrollback control
- The scrollback is alacritty's default size (`session.rs:414`, `Config::default()`), with no
  setting. Long agent runs and build logs exceed it, and search "cannot retrieve output
  already evicted". There is no Clear scrollback action and no key for the top or bottom, only
  Shift+PageUp / PageDown.
- Suggestion: a "Scrollback lines" setting (memory is the app's second priority, so say what a
  line costs in the description), a `ClearScrollback` action, and Shift+Home / Shift+End to
  scroll to the top / bottom.

### E3. Use the prompt marks for navigation
- The shell integration already knows where every prompt and command starts (OSC 133), but
  uses it only for status and history.
- Suggestion: Ctrl+Shift+Up / Down scroll to the previous / next prompt (Windows Terminal, VS
  Code, kitty have this); "Copy output of last command" in the E1 menu. The second one fits
  this app especially well: copying a failed command's output into an agent tab is the most
  common hand-off between a shell tab and an agent tab.

### E4. Resume the conversation on a restored Claude tab
- **Done** (f2fa3b1): hooks carry `session_id` (`conv=`), `tabs.json` saves it, and a restored
  tab shows a bar with Resume it / Start new (buttons, not Enter: Claude Code is already
  running behind it). Checked live (2.1.322): `--resume <hook id>` keeps the id; an unknown id
  exits 1 before any hook, and the app then starts a new conversation with a warning. Copilot
  stays "new session".
- Problem (old review #22, still under "Later"): a restored tab named after a conversation
  starts a fresh `claude` with nothing saying the conversation is gone, against FEATURES
  "Clearly distinguish restoring a layout from restoring ... an agent's conversation".
- New angle: Claude Code's hook payloads carry a `session_id` (`agent-status/src/ipc.rs`
  tests). Saving the tab's last session id in `tabs.json` lets a restored tab offer exactly
  that conversation: "Resume this conversation (Enter) · Start new". This avoids the objection
  to `--continue` (it picks the folder's latest conversation, maybe another tab's).
- To check first: that `claude --resume <id>` accepts the id the hooks report, and what a
  resume of a deleted conversation prints. Copilot would stay "new session" unless it offers
  the same.
- Needs the user (startup behavior).

### E5. Show what the agent changed
- **Steps 1-2 done** (e3c072a): the explorer colors changed files and their folders; the hover
  card lists the first 8 changed files under `+N`, click opens them in the viewer. Step 3 (Diff
  panel) is still parked.
- The question after every agent turn is "what did it touch?". Today the answer is a `+N`
  line count in the hover card; the explorer dims ignored files but does not mark changed ones,
  and the Diff panel is parked.
- Suggestion, in steps: (1) color modified and untracked entries in the tree, and their parent
  folders, from the `git status` the card already pays for; (2) clicking `+N` lists the
  changed files, each opening in the viewer; (3) the parked Diff panel. Step 1 alone makes the
  explorer useful for review rather than only navigation. Consider unparking the Diff panel:
  it is the feature that most reduces switching to an IDE.

### E6. Explain the app from inside the app
- A first start shows one shell tab. Nothing says that `+` holds agents, that badges mean
  something, that Ctrl+Shift+A jumps to the tab that needs you, or that typing `claude` in a
  shell tab also gets status. The eight badge states are defined only in a README table.
- Suggestion:
  - A one-time, dismissible "Getting started" card (three lines: open an agent from `+`, what
    the orange badge means, the attention key), shown in the first window only.
  - A status legend: an entry on the About page or a small `?` next to the attention button,
    listing each badge with its name.
  - Disabled agents in the `+` menu and empty state say how to get them (tooltip: "Not found
    on PATH. Install: npm install -g ...").
  - The Keyboard settings page already is the cheat sheet; give it a shortcut or a title bar
    tooltip so it is found.

### E7. Custom entries in the `+` menu
- The menu lists discovered shells and two agents. `claude_args` / `copilot_args` are global,
  so "Claude in plan mode" and "Claude with skip-permissions" cannot both be one click away,
  and a dev server, a REPL or an `ssh` to a host without `agentws-server` need a shell tab plus
  typing every time.
- Suggestion: a `launchers` list in `settings.json` (name, base launcher id or command,
  arguments, optional folder, optional icon from the bundled set), shown in the `+` menu after
  the built-in ones and saved in `tabs.json` by id. This also absorbs the backlog's
  "Configurable terminal icon" and gives the new-tab folder picker a place for recent folders.

### E8. Appearance gaps
- UI text size: only the terminal font is adjustable. Sidebar, menus and settings stay at one
  size, which is small on a HiDPI laptop at 100 % and for low-vision users. One "Interface
  size" setting (scaling the rem size) covers it.
- Follow the OS theme: README says "Following the OS theme is not included". Add "System" to
  the Theme dropdown; it changes only when the OS reports a change, so it costs nothing idle.
- Cursor: no setting for shape (block, bar, underline) or blink. Programs can set it by escape
  sequence, but the default is a common preference. Blink needs a timer: off by default and
  tied to "Activity animations".
- Reduced motion: when the OS asks for reduced motion, start with Activity animations off.

### E9. Settings edits apply when the file changes
- Edits to `settings.json` in another editor apply only when the settings page opens, the file
  is saved in the viewer, or something else changes. The app already watches folders for the
  explorer; watching one file is event-driven and fits "no work when idle". It matters most
  for keybindings, which are partly file-only (key sequences).

### E10. Install the Copilot mode extension from Settings
- Today: copy two files by hand into `~/.copilot/extensions/bowarp` (README:305-316), and
  repeat after every app update. Suggestion: a row on Settings → Terminal showing "Not
  installed / Installed / Older version" with Install and Remove buttons. It writes into the
  user's Copilot folder, so it must stay an explicit click, never automatic (the app's rule of
  not touching the user's CLI config).

## Missing

### M1. Split panes
- FEATURES lists "Support split panes, adjustable pane sizes" and shortcuts for "tabs and
  panes"; the README's first line says "side by side". The app shows one terminal at a time
  and BACKLOG.md has no pane item at all.
- Why it matters here more than in a plain terminal: the typical use is watching one agent
  while working in a shell on the same folder, or comparing two agents. Status badges reduce
  the need, but do not replace seeing the output.
- Smallest useful version: one vertical split of the terminal area showing two existing tabs
  (the selected tab plus one "kept visible" tab picked from the tab menu), no nested layouts.
  The sidebar stays the single list of sessions.
- Needs the user: build that, or remove panes from FEATURES and the README wording.

### M2. Reaching the user outside the window
- The app's main promise is "know when an agent needs you". Today that works only while the
  user looks at the window: no taskbar flash, no OS notification, no sound. Users leave agents
  running precisely to do something else.
- Tracked as Tier 1 #11 (taskbar flash, waiting on the user's yes) and a parked sound item
  (blocked on an ALSA build dependency). Recommendation: treat this as the top feature gap,
  ahead of everything in Enhance. Order: flash (already designed), then OS notifications
  behind their own switch (they work on Wayland, where the flash does not), then sound.

### M3. Agent status for remote tabs
- Tracked under Remote sessions ("Shell integration and status on the server"), after several
  server-side items. From a user's view it should come first: a remote agent without status is
  a plain ssh window, and the other remote items (client counts, `show`) are operator tools.

### M4. Update check
- Installing is manual from GitHub releases and nothing tells a user a newer version exists;
  the app ships a patch release per feature, so installs go stale quickly.
- Suggestion: "Check for updates" on the About page, on click only (one request to the
  releases feed, no background polling, no account), showing the newer version and a link to
  its notes. An automatic check, if wanted later, is a switch that starts off.

### M5. Quick open
- The explorer is a tree only. In a repository of any size, opening a known file means
  expanding folders by hand, and the tree has no keyboard navigation yet (old review #23).
- Suggestion: once the command palette exists (backlog), give it a file mode (fuzzy match on
  paths under the tab's folder, ignoring git-ignored entries), read off the UI thread.

## Added after the review

### E11. Back, Forward and Last tab
- **Done** (54742c7): ← → buttons in the sidebar header and Ctrl+Alt+Left / Right walk the
  selected tabs like a browser's history; Ctrl+` switches with the last tab. Closed tabs leave
  the history; all three are rebindable. GNOME's default workspace switch also uses
  Ctrl+Alt+Left/Right.
